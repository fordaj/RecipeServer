# The caddy bundle (`tools/caddy/`)

[Caddy](https://github.com/caddyserver/caddy) is the HTTPS front-end for the optional HTTPS mode: when HTTPS is enabled in the configuration, Caddy listens on the configured port on all interfaces, terminates TLS with a certificate issued by the bundled mkcert, and reverse-proxies to the embedded server on the loopback interface (see "Optional HTTPS front-end" in `src/recipeserver/https_setup.py`, documented in `src/recipeserver/https_setup.py.md` in the repository). The site then serves HTTPS for every address this machine has, which is also what makes the dictation button work without external tooling.

## Layout

```text
tools/caddy/
  update.sh                     # refresh from caddyserver/caddy releases
  v2.11.9/
    macos-arm64/caddy
    macos-x86_64/caddy
    linux-arm64/caddy
    linux-x86_64/caddy
    windows-arm64/caddy.exe
    windows-x86_64/caddy.exe
```

Only `caddy` (plus the upstream `LICENSE` kept from the release archives) is bundled; the archives also carry a README, which is dropped.

## `update.sh` in detail

Archives are `.tar.gz` (macOS/Linux, named `caddy_<version>_{mac,linux}_<arch>.tar.gz`) and `.zip` (Windows, named `caddy_<version>_windows_<arch>.zip`). Each archive is flat and carries the `caddy` binary and the upstream `LICENSE`. The script:

1. Resolves the tag (latest release, or `--tag vX.Y.Z`), validating the tag shape (`vX.Y.Z...`). `--repo`/env `CADDY_REPO` overrides the upstream repository slug (default `caddyserver/caddy`; env `CADDY_TAG` pins the tag, overridden by `--tag`).
2. Downloads via `gh`, then verifies every downloaded archive against the upstream `checksums.txt` (`shasum -a 256 -c` or `sha256sum -c`). A missing checksum for a downloaded asset is fatal; a release without any checksums file only warns.
3. Extracts each archive (`tar` for `.tar.gz`, `unzip` for `.zip`), copies the binary into `v<tag>/<platform>/`, makes it executable, and keeps `LICENSE` alongside it. The `freebsd_*` and `armv5`/`armv6`/`armv7`/`riscv64`/`ppc64le`/`s390x` assets are skipped — only the six bundled platforms are installed.
4. Swaps in the new version directory and deletes superseded `v*/` ones, then smoke-tests the host binary (`caddy version` exits 0).

Unknown arguments exit `2`. `--dry-run` lists assets and what would change without touching anything.

The `<platform>` directory names match the env cascade: `macos|linux|windows` + `x86_64|arm64`. The pinned tag is `v2.11.9`, selected via `CADDY_VERSION_DIR` in `scripts/.common.env` and exposed to scripts as `CADDY_BIN` by `scripts/.<platform>.env`; see [../../scripts/env.sh.md](../../scripts/env.sh.md).

## How the repository uses it

`src/recipeserver/https_setup.py` owns the runtime lifecycle: it resolves the binary (the `CADDY_BIN` environment variable, this bundle, or `caddy` on `PATH`), writes a `Caddyfile` that reverse-proxies to the embedded server's ephemeral loopback port, starts Caddy on the configured port, and stops the process on app shutdown or when HTTPS is disabled in the configuration. The certificate is generated by the bundled mkcert; mkcert's one-time CA install is the only step that asks for anything.
